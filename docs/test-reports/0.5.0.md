## Round B — the General tab saves real settings (26.09.2026)

**Scope:** `includes/admin/class-general-settings.php` (new), rewritten

**Controls:** total limit, per-tab limit, comparison rule, ignored categories,

**Level 0 — PASS 5/5** (`runs/level0-20260926-075206/`): syntax 48 files on
PHP 8.1 and 8.3; entrypoints on PHP 7.0+; WPCS + Security + PHPCompatibility
0 errors / 0 warnings; PHPStan level 6 no errors; i18n POT fresh, 225 entries,
`ru_RU` complete (42 new strings translated, 3 obsolete removed).

**Level 1 on `main` — PASS 12/12 in 57 s** (`runs/level1-20260926-075313/`):
core logic 41/41, REST 12/12, frontend 17/17, table 7/7, activation
(WP 7.1.2 / WC 11.1.2 / PHP 8.3) + data version, admin browser **18/18**
(including the new save → reload → search → exclusions → reset cycle),
without-WooCommerce 4/4, uninstall keep/clean, WP_DEBUG clean, Plugin Check
0 errors / 0 warnings.

**Defects found and fixed in the round:**

1. **403 on save — `&amp;` in the handler URL.** `wp_nonce_url()` (and
   `add_query_arg()`, even after `esc_url_raw()`) return an HTML-escaped URL;
   inside the inline JSON the browser posted the nonce in a parameter named
   `amp;_wpnonce`, so every save failed the nonce check. Fixed by building the
   URL manually (`General_Settings::handler_url()`); confirmed in the browser —
   the save now returns HTTP 200 with the sanitized settings.
2. **Playwright could not find the product-search field.** `data-testid` on a
   `TextControl` does not reliably reach the `<input>`; every control is now
   wrapped in a `<div data-testid="…">` and the e2e locators use
   `[data-testid="…"] input|select`.

**Held decisions:** save/reset go through `admin-post.php` answering JSON, not
new public REST routes; nonce + capability checks live inside each handler
(WPCS only recognises them in the same scope) and `$_POST` is read there, with
helpers receiving plain arrays; reset touches only `General_Settings::SCOPE`.

**Deferred (questions to the user):** “where to show the button” (belongs to the
Buttons & toasts tab, duplicating it in General was rejected) and the
second-click action (no settings key exists yet).

## Round C2 — toasts + phone offsets, two defects closed (26.09.2026)

**Scope:** toast positions (desktop/phone), toast duration, four editable toast
templates with `{product}` / `{category}` / `{count}` / `{limit}`, phone scroll
offsets; plus the two defects found by the first level-1 run in the new chat.
No version bump (headers stay 0.4.1 until Round F); `uninstall.php` untouched —
all new keys live inside the single `rvn_compare_settings` option.

**New settings keys** (all inside `rvn_compare_settings`): `toast_tpl_added`,
`toast_tpl_removed`, `toast_tpl_limit`, `toast_tpl_limit_tab` (empty = built-in
translation), `scroll_offset_top_mobile`, `scroll_offset_bottom_mobile` (empty =
the computer value). Existing keys `toast_position`, `toast_position_mobile`,
`toast_duration` gained their admin UI in this round.

**Defects closed (both reported in Round 25):**

1. `includes/admin/class-buttons-settings.php` — PHP Warning “Array to string
   conversion”. Real source is `scope_input()`: `(string) $post[ $key ]` on a
   non-scalar field. Fixed with `is_scalar()` in `Buttons_Settings::scope_input()`,
   `General_Settings::scope_input()`, `Settings::sanitize()` and
   `Buttons_Settings::contexts()`. Proven by a runtime probe posting
   `show_contexts[] = [ 'shop', [ 'evil' ], 'cart' ]` → sanitized to
   `shop|cart`, **0 warnings** in `wp-content/debug.log`.
2. React `validateDOMNesting` — `<div>` from `CheckboxControl` inside our `<p>`
   wrapper in `wp-dev/admin-ui/src/index.js`. The wrapper is now a `div`.
   Confirmed in the browser: the “no plugin JS errors” check is green.

**Defect found and fixed by the new e2e check:** the toasts block did not save —
`Buttons_Settings::scope_input()` carries its own key list and the new keys were
missing from it, so every toast field was dropped on save. Caught by the fresh
“уведомления пережили перезагрузку” assertion before it could ship; keys added.
