## Оба дефекта из прошлого раунда — закрыты и доказаны

1. **PHP Warning «Array to string conversion».** Настоящий источник я нашёл не
   там, где думал раньше: виноват не только `contexts()`, но и `scope_input()` —
   там значение из `$_POST` приводится к строке. Теперь `is_scalar()` стоит в
   обоих `scope_input()`, в `Settings::sanitize()` и в `contexts()`.
   Доказательство: я специально отправил враждебный запрос с
   `show_contexts[] = ['shop', ['evil'], 'cart']` — на выходе `shop|cart`,
   **ноль** записей в `debug.log`.
2. **React «validateDOMNesting».** Обёртка вокруг `CheckboxControl` в
   `wp-dev/admin-ui/src/index.js` была `<p>`, а компонент рисует `<div>`. Теперь
   это `<div>`. Проверка «Нет ошибок JavaScript от плагина» снова зелёная.

## Что добавлено (раунд C2)

### Уведомления — блок на вкладке «Кнопки и уведомления»

- **Позиция на компьютере и на телефоне** — по отдельности: сверху/снизу ×
  слева/по центру/справа, плюс «по центру экрана». На телефоне по умолчанию
  «снизу по центру».
- **Длительность показа** — 0…15000 мс. 0 означает «не закрывать самому»,
  посетитель закроет крестиком.
- **Четыре настраиваемых текста**: при добавлении товара, при удалении, когда
  список заполнен, когда заполнена вкладка категории.
- **Подстановки:** `{product}`, `{category}`, `{count}`, `{limit}`. Например:
  `Добавлен {product}` или `{category}: {count} из {limit}`. Пустое поле —
  встроенный перевод, поэтому после обновления ничего не меняется для тех, кто
  не трогал настройки. Подставляются значения текстом, так что HTML в шаблоне
  отображается как есть и ничего не выполняет.

### Отступы для телефона

`scroll_offset_top_mobile` и `scroll_offset_bottom_mobile` — теперь отдельные
поля, а не «одно значение на все экраны». Пустое значение наследует значение
компьютера; заполненное уходит в CSS-переменные внутри медиазапроса
`max-width: 767px`. Всё это живёт внутри одной опции `rvn_compare_settings`,
поэтому `uninstall.php` не трогался.
